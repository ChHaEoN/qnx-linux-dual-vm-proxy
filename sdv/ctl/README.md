# sdv/ctl: the claim side of kind 2

Phase 8's claim node and its ROS-free core: Autoware's gate output, one
`autoware_control_msgs/msg/Control` at a time, packed into a kind 2 `ctl` frame and sent to the QNX guest's
monitor (`:7150 svc 500`; `:7151 stamp` for pre-registered timing runs only), with the verdict published on
`/qnx_monitor/verdict` as an advisory. The frame, rules and verdict message are defined by the code
in this directory.

| file | what it is |
|---|---|
| `ctlframe.py` | The kind 2 frame inside the repo's 64-byte frame (`ipc-test/common/frame.h`): its constants, `encode` (an honest request), `pack_bits` (each slot's exact binary32 bits, for injection), `decode_request` and `decode_reply` (every layout fault refused), `interval_ms` (0 for the first Control, saturated at 0xFFFF), and `load_contract`, which loads the kind 2 contract `vss_ctl.py` by path and refuses one whose FORMAT is not the int 1, whose DIGEST is not the FNV-1 32 of its UIDs, or whose compiled profile has `steer_max` outside (0, 1.0] rad. Standard library only. |
| `ctlrules.py` | The Python reference judge of 2.3 (reasons 10, 8, 9, 11-19, first failure wins), with `sdv/frame/rules.py`'s `vss_tan` for rule 17. The oracle the C monitor is compared with; nothing in the node imports it. |
| `ctlclient.py` | The core: one frame per counted Control, the bridge's connection rules (connect at the first Control, lazy reconnect with a backoff, the peer-closed check before each send, one request outstanding, a 1-deep queue whose replaced frame is a drop, `lost_on_reconnect` apart from it), the accounting `controls = replied + drop + lost_on_reconnect`, the intake pause, profile 2's bounded window, the injections, the reply log and its header, and 2.6's message from the one pure function `verdict_message`. The design values (reply and connect timeouts 500 ms, the backoff from 100 ms doubling to 2 s, the odometry freshness window 100 ms) are in it, each with its reason. Standard library only. |
| `ctl_claim_node.py` | The rclpy shim: subscribes to `/control/command/control_cmd` and `/localization/kinematic_state` (KEEP_LAST 1), hands each Control to the core with the latest odometry, and publishes 2.6's message on `/qnx_monitor/verdict` (RELIABLE, KEEP_LAST 10) and nothing else, never `/diagnostics`. It imports rclpy and the message packages inside `main` only, and no KUKSA client, no gRPC, nothing of `sdv/frame` and not `ctlrules`. |
| `ctlreplay.py` | The replay: reads a recorded drive's export, checks it whole, and sends its Controls through the same core at their recorded receive spacing, each with the latest odometry received before it and its interval from the recorded stamps. No ROS. |
| `ctl_export.py` | A bag to the export (2.7's JSON Lines: one record per message in receive order, then a summary with the message counts and the bag's sha256 per file). `rosbag2_py` inside `main`; the conversion is pure functions. It refuses an existing output, and an output or a bag inside the repo or any work tree. |

## Where each runs

- **The Jazzy container** (Autoware's Jazzy release image, Python 3.12): `ctl_claim_node.py` beside a running
  Autoware, and `ctl_export.py` over a recorded bag. Both need the image's rclpy and message packages; nothing
  else of this directory needs ROS.
- **The bare-metal host's Python** (or any Python 3.12 without ROS): `ctlreplay.py`, against the guest's
  monitor, when ROS does not run there or a recorded drive is to be replayed.
- **CI**: `tests/test_sdv_ctl.py` runs every module without ROS, against stand-ins for rclpy, the message
  packages and rosbag2_py, and against a Python peer on loopback in place of the monitor; `ctlrules.py` runs
  only there. The kind 2 contract is generated by `sdv/vss/generate.py` from WP1b on (`sdv-out/gen/vss_ctl.py`,
  the default `--contract`); until then the tests use the fixture `tests/fixtures/ctl-py/vss_ctl.py`.

## What they write

- **The node and the replay**: a run directory given by `--out` (never inside the repo or another work tree,
  empty if it exists) holding `replies.jsonl`: a header line (format 1, kind 2, the mode, the target, the stamp
  flag, the profile, the demo window, the injections, the pause, the contract's sha256 and digest, the design
  values; the replay adds the export's sha256), one line per frame outcome (`seq`, the 64 bytes sent as hex,
  `outcome` replied, drop or lost, `verdict`, `reason`, the client's monotonic ns), and a summary line with the
  counters and the identity. The node also publishes on `/qnx_monitor/verdict`; neither writes anything else.
- **The export**: the one file given by `--out`, outside every work tree. Recordings, exports and run
  directories stay local and out of the repo.

Injections (`--inject SEQ:MODE`: nan, undef, reserved, profile0, kind9, and the value injections interval,
speed, accel, jerk, steer, steer-rate, lat-accel, overspeed, rolling-back, which give reasons 9, 10, 10, 8, 5 and
11-19), the intake pause (`--pause AFTER_SEQ:DURATION_MS`) and profile 2's window (`--demo START_MS:DURATION_MS`,
never longer than its `run_window_max_ms`) are refused on a stamp target, so none of them can enter a timing run.
A rolling-back injection is also refused when the contract's `OVERSPEED_MARGIN` is under its |v_meas| as packed,
since rule 18 would then come before 19 for a small `v_cmd`. Any injection is refused at start, too, when the
contract leaves it no frame that carries its reason for a profile the run may send (a `steer_max` with no binary32
above 0 below it, a limit whose 1.5-fold has no binary32 above the limit, a `DT_MAX_MS` that is not an int below
0xFFFF, a constant that puts rule 18's or 19's threshold out of reach), so the core never raises for an injection.

## What this does not demonstrate

- That the monitor is in the control loop: it is not. The node observes the gate's output after the gate sent it;
  the verdict is an advisory nothing in Autoware consumes.
- That Autoware's own faults would be caught: the injection point is after the gate, which clamps first, so a
  reject is expected only from an injected fault, the intake pause or profile 2's window; any other reject is a
  finding of the run that shows it (WP4b).
- Any timing: the reply log orders events; the log makes no performance claim, and the replay follows the recorded
  spacing only as closely as its host allows.
- That the monitor judges kind 2 as `ctlrules.py` does (the integration stage's contract test, against WP1a's
  native build), or anything about the generated contract (WP1b), the guest (WP5) or a real Autoware run (WP4b).
