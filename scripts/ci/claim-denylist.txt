# claim-denylist.txt -- claim strings the committed data does not support.
#
# Format, one rule per line:
#     <regex>  <TAB or two+ spaces>  <why this claim is not supported>
# A line beginning with '!' is an EXEMPTION instead: a sentence no rule may fire
# on, with the reason it was inspected and cleared. Blank lines and '#' comments
# are ignored. Extend this file freely; no Python change is needed.
#
# HOW A RULE FIRES. scripts/ci/claims_gate.py splits prose into SENTENCES (not
# lines -- the docs wrap) and reports a match only when the sentence is an
# ASSERTION. A sentence carrying a negation ("no", "not", "never",
# strike-through) or a planned-marking ("design intent", "never built",
# "superseded") is not a violation.
#
# That exemption is load-bearing, not a loophole. This project's honest framing
# requires sentences like "Nothing in it is certified" and "No certified Type-1
# isolation" -- a naive substring denylist would fail the build for exactly the
# text that makes the README truthful. Verified 2026-09-19: all 2 ASIL, all 10
# "certified" and all 4 "Graviton" sentences in README.md classify as negated or
# planned, and none as asserted.
#
# A RULE CAN OUTLIVE ITS PREMISE, and then it bans the evidence instead of the
# lie. That has now happened twice in this file -- see the acceleration and
# Graviton sections. When a rule is narrowed, the reason is written down here
# with its date, and both directions are pinned in tests/test_prose_gate.py.

# --- acceleration. REWRITTEN 2026-09-20; the reason matters more than the rules.
# The three rules that used to live here banned any claim that a measurement was
# taken under KVM. They were correct when written, because no QNX guest had ever
# run under KVM anywhere, so every such sentence was false by construction.
# That premise died twice:
#   2026-09-19  guest latency measured with QNX as a KVM guest, governor pinned
#   2026-09-20  boot timing under KVM on two hosts, byte-identical image
# Keeping the blanket ban would have made the project's own measurements
# unpublishable. What is STILL universally false is narrower and is what these
# rules now protect:
#   * a hardware-timed HYPERVISOR number. The QNX Hypervisor cannot run under
#     KVM at all -- it needs EL2 and ARM KVM does not nest on A78AE -- and its
#     native (A4) figures are unpublished. Nothing has ever timed QHV on silicon.
#   * that the PUBLISHED A1-A3 legs were KVM-accelerated. Every one ran TCG.
\bhardware[- ]timed\b[^.]{0,60}\b(hypervisor|QHV|qvm)\b	no hardware-timed hypervisor number exists anywhere; QHV needs EL2 and ARM KVM does not nest on A78AE
\b(A1|A2|A3|cloud leg|Orin plain leg)\b[^.]{0,70}\b(under|on|with)\s+KVM\b	the published A1-A3 legs all ran under TCG, not KVM
\bKVM[- ]accelerated\b[^.]{0,40}\b(A1|A2|A3|cloud|twin diff|IPC)\b	no KVM-accelerated figure exists for those legs; they are TCG

# --- the cloud LEG. Still never built, and that is separate from the boot arms.
# AWS has been used four times (a t4g.small /dev/kvm probe, an a1.metal hang
# reproduction, an a1.metal control/test pair, and the 2026-09-20 twin boot
# measurement), so "nothing ran on AWS" is false. What does not exist is a cloud
# LEG in this project's sense: a QHV host plus guest running the IPC benchmark.

# Keyed on the HOST token, never on the word "cloud": "cloud leg" is this
# project's NAME for architecture A1, which ran on the local Windows PC, so
# banning "cloud" near "IPC" would ban the project's own vocabulary.
\b(Graviton|AWS|EC2|a1\.metal|c7g|t4g)\b[^.]{0,80}\b(IPC|latenc\w*|throughput|p50|p99|benchmark\w*)\b	no IPC, latency or throughput figure was ever taken on a cloud host; the only cloud measurement is boot timing (2026-09-20)
\b(IPC|latenc\w*|throughput|p50|p99|benchmark\w*)\b[^.]{0,80}\b(Graviton|AWS|EC2|a1\.metal|c7g|t4g)\b	no IPC, latency or throughput figure was ever taken on a cloud host; the only cloud measurement is boot timing (2026-09-20)

# --- Graviton as a LEG or a RUNTIME HOST. Narrowed twice.
# 2026-09-20 (first): the rule was a bare \bGraviton\b, from when every Graviton
# sentence here was false. It began banning the cross-vendor defect evidence.
# 2026-09-20 (second): "figure|number|boot-time" came out of the rule too,
# because a1.metal IS Graviton1 and it produced real boot timings that day. What
# stays banned is the STRUCTURAL claim -- a Graviton leg, twin or runtime host --
# because the c7g.large runtime host was designed and never built.
\bGraviton\b[^.]{0,80}\b(leg|twin|runtime host)\b	the Graviton runtime host was designed and never built; no leg ran there
\b(leg|twin|runtime host)\b[^.]{0,80}\bGraviton\b	the Graviton runtime host was designed and never built; no leg ran there

# --- safety / certification: none of this exists and none of it is claimed.
\bASIL\b	no ASIL claim is supportable; SDP 8.0 is not QNX OS for Safety
\bcertifi(ed|cation)\b	nothing here is certified; state the gap instead
