# K12 settled: the BSP zip's startup lib + `armv8_fm` board build unmodified under the win64 SDP 8.0 toolchain

Compile-only, no board involved. Executed 2026-09-09 (UTC afternoon) on the Windows build host by the
orchestrating session, as "first action today" #1 of the synthesised plan. Evidence class: **VERIFIED**
(commands run, exit codes and outputs recorded here; our build's symbol-name listing under `raw/`).

## What was run

Environment: `call C:/Users/<user>/qnx800/qnxsdp-env.bat` (sets `QNX_HOST`, `QNX_TARGET`, `MAKEFLAGS=-I.../usr/include`, PATH).
Tree: the BSP zip `BSP_hyp-guest-arm_be-800_SVN1018940_JBN323.zip` extracted to a private temp directory
(`.../Temp/orin-native-port-bsp/`, outside the repo). Nothing in the zip was edited.

| step | command (cwd) | result |
|---|---|---|
| 1 | `make` in `boards/armv8_fm/aarch64/le` straight away | `_start.o` assembled; `board_smp.c` fails: `startup.h: No such file or directory` — the board expects the lib's public headers in `<bsp>/install/usr/include` |
| 2 | `make hinstall` in `src/hardware/startup/lib` | exit 0; 31 headers installed under `install/usr/include` |
| 3 | `make` in the board dir again | C files compile; `callout_reboot_armv8-fm.S` fails: `asmoff.def: No such file or directory` — generated by the lib build, not by `hinstall` |
| 4 | `make install` in `src/hardware/startup/lib` | **exit 0**; `install/aarch64le/usr/lib/libstartup.a` (725,640 B) and `install/usr/include/aarch64/asmoff.def` (1,199 B) produced |
| 5 | `make install` in `boards/armv8_fm/aarch64/le` | **exit 0**; `install/aarch64le/boot/sys/startup-armv8_fm` = 632,224 B, plus `.map` and `.pinfo` |

So the correct order is the BSP's own: lib (build + install) first, then the board. `boards/common.mk`,
`recurse.mk`, `qrules.mk` all ran unmodified; no makefile, flag or path edit was needed. K12 is therefore
VERIFIED, and the plan's "P — prep" row loses its main uncertainty.

## What the build tells us

- Lib compile flags as used by the zip's makefiles (from the log):
  `-Wall -DNDEBUG -Wno-error=missing-prototypes -O2 -fomit-frame-pointer -fno-PIE -DBUILDENV_qss -mgeneral-regs-only -mstrict-align -fno-store-merging`.
  Board files add `-fno-gcse -fno-inline-small-functions`. `-fno-auto-inc-dec` is **not** in either set, so a
  from-source lib is a drop-in place to carry that flag, as the project's rebuilt `startup-qemu-virt`
  (`orin-native/startup/qemu-virt/`) does — outside this port's scope.
- All the pieces the port plan relies on are linked into a from-source `startup-armv8_fm` (symbol names from the BSP
  source; the link listing was withdrawn on 2026-09-27, 4.6(c)): `gic_v3_initialize`, `gic_v3_set_paddr_range`, `psci_smc`,
  `psci_smp_start`, `psci_cpu_id` (library version — the port overrides it), `hyp_enable_el2_host`,
  `hypervisor_init`, `fdt_init`, `init_raminfo_fdt`, `fdt_psci_configure`, `init_qtime_v8gt`, `cpuid_a78ae`.
  Not linked (expected — `armv8_fm` is not UEFI-entered): `efi_entry_point`, `uefi_init`.
- A comparison of this build against the SDP-shipped `startup-armv8_fm`, made on 2026-09-09 from symbol-name
  listings of the shipped binary, was withdrawn on 2026-09-27 under NC QDL v7 clause 4.6(c), with those listings.
- Nothing from the build (lib, startup, headers) enters the repo: only these notes and our build's symbol-name list.
